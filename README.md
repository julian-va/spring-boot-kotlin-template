# spring-boot-kotlin-template

Minimal Spring Boot service in Kotlin on Java 25, with actuator, OpenAPI documentation, JaCoCo coverage enforcement and two OpenCode skills.

## Requirements

- **JDK 25**, pinned through `java.toolchain` in `build.gradle.kts`. It must already be installed and discoverable: `settings.gradle.kts` has no toolchain resolver, so Gradle fails instead of downloading one.
- **No Gradle install needed.** Use the wrapper (`./gradlew`), which pins Gradle 9.8.1.
- **No separate Kotlin install.** The Kotlin Gradle plugin (`2.3.21`) and `kotlin-reflect` come from Maven Central.

## Run

```bash
./gradlew bootRun
```

Or build the executable jar:

```bash
./gradlew bootJar
java -jar build/libs/spring-boot-kotlin-template-0.0.1-SNAPSHOT.jar
```

There are no web controllers yet, so `GET /` returns 404. The HTTP surface is:

- `GET /actuator/health` — `{"groups":["liveness","readiness"],"status":"UP"}`
- `GET /v3/api-docs` — OpenAPI 3.1 document
- `GET /swagger-ui.html` — Swagger UI (redirects to `/swagger-ui/index.html`)

## Test

```bash
./gradlew test
```

Run a single test class:

```bash
./gradlew test --tests "jvacloud.spring_boot_kotlin_template.OpenApiDocumentationTests"
```

## Coverage

`./gradlew check`, and therefore `./gradlew build`, runs `jacocoTestCoverageVerification` with an **80% instruction minimum**.

- Reports: `build/reports/jacoco/test/html/index.html` and `build/reports/jacoco/test/jacocoTestReport.xml` (both gitignored).
- Excluded from analysis: `SpringBootKotlinTemplateApplication`, the `SpringBootKotlinTemplateApplicationKt` facade that Kotlin generates for the top-level `main`, and data-only code (DTOs, JPA entities, bean configuration and domain exceptions). See `jacocoExcludes` in `build.gradle.kts`.
- **Kotlin specifics** (verified against this project):
  - JaCoCo filters the members generated by a `data class` (`copy`, `componentN`, `toString`, `equals`, `hashCode`), so they do not inflate the report.
  - The `$default` bridge generated by default arguments **is** counted. A default value that no test exercises shows up as uncovered instructions.
  - Every constructor `val` generates a getter that counts as executed only when read.
- **Current caveat:** the two application classes are the only main classes, so the bundle is empty and the gate passes vacuously. It starts enforcing as soon as a **non-excluded** class exists.

## Notes on the setup

- **Spring Boot 4 renamed the starters.** This project uses `spring-boot-starter-webmvc` (not `-web`) and `spring-boot-starter-webmvc-test` plus `spring-boot-starter-actuator-test` (not `spring-boot-starter-test`). Adding the Boot 3 names pulls in a duplicate legacy stack.
- **Virtual threads are on.** `spring.threads.virtual.enabled: true` makes Tomcat serve requests on `java.lang.VirtualThread` instead of the platform-thread pool.
- **Springdoc is pinned by hand.** `springdoc-openapi-starter-webmvc-ui:3.1.1` is the Boot 4 line (2.x targets Boot 3) and the Spring Boot BOM does not manage it, so the version is explicit in `build.gradle.kts`. `OpenApiDocumentationTests` fails if it stops serving `/v3/api-docs`. **In production, turn it off**: `springdoc.api-docs.enabled=false` and `springdoc.swagger-ui.enabled=false`.
- **Jackson 3 with Kotlin.** Boot 4 uses Jackson 3 (`tools.jackson`), so the project needs `jackson-module-kotlin` plus `kotlin-reflect`; without them Kotlin classes without a no-arg constructor do not deserialize.
- **The package name contains an underscore** (`jvacloud.spring_boot_kotlin_template`). It is deliberate: Initializr rejected the hyphenated artifact name; `HELP.md` explains this but is untracked (listed in `.gitignore`).
- **No CI, no linter/formatter, no LICENSE.** There are no workflows in this repo, so the coverage gate only guards local builds.
